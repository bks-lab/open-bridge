Claude Code skill · spec-kickoff

Start a build the right way

A phased, checkpointed kickoff for beginning a substantial build — Andrej Karpathy's three layers (spec → verifier → environment), expressed through Claude Code's own primitives. It produces one self-contained SPEC.md that ends in an end-to-end verification step, then hands off to the build.

§1 What it is

Not a new framework

Not

A new methodology, a four-file .specify/ tree, a "constitution" to author, or a hooks-101 tutorial. The kickoff doesn't reinvent any of that.

But

Anthropic's native interview → SPEC.md → verify-loop pattern, plus Kiro's EARS requirements and the verification ladder — wired into the environment you already have. One SPEC.md per kickoff is the right weight.

The skip-gate comes first. If you could describe the change in one sentence, it's a quick fix (≲10 min), or you're mid-build — the skill says so and steps aside. The method is for substantial new builds, never a ceremony tax.
§2 The shape

Three layers

Layer 1

Spec

An interview separates the goal from the task, cuts the thinnest verifiable slice, and writes precise EARS requirements. You own the understanding — the agent does the thinking.
→ produces the goal, slices & EARS requirements
Layer 2

Verifier

The model is a ghost — an imitator of human text, so its output is plausible-shaped by default and must be checked. Each criterion gets the strongest available check + a gate.
→ produces the verification plan
Layer 3

Environment

The workshop the spec & verifier live in: context, reusable skills, guardrails. On a built-out setup it already exists — the skill points at it instead of rebuilding it.
→ wires into CLAUDE.md · skills · hooks

§4 Layer 1

The spec interview

  1. 1Goal, not task. Separate the task from the decision the output drives — the "done" a human must own.
  2. 2Agile slice. The thinnest end-to-end slice that has a verifiable check; defer the rest.
  3. 3EARS requirements. Force edge cases & failure modes into the open — each line becomes an acceptance check.
EARS patternShapeUse for
UbiquitousTHE SYSTEM SHALL <response>always-true invariants
EventWHEN <trigger> THE SYSTEM SHALL <response>reactions to events
StateWHILE <state> THE SYSTEM SHALL <response>behaviour during a mode
OptionalWHERE <feature> THE SYSTEM SHALL <response>feature-flagged behaviour
UnwantedIF <condition> THEN THE SYSTEM SHALL <response>edge cases & failure modes
§5 Layer 2

Make it checkable before building

Map every acceptance criterion to the strongest available check, and fall down the ladder only when the rung above isn't available.

1
Deterministic — test · build exit code · linter · typecheck · diff-against-fixture. Prefer this.
↓ no deterministic check?
2
External signal — CI per SHA · deploy probe · a reference doc / historical report · real data.
↓ no ground truth?
3
Judge — fresh-subagent / model critic, scoped to the criteria, with the bias caveat.
↓ can't even judge?
✗
UNVERIFIABLE — make it verifiable, or don't ship it.

Gate strength — pick per criterion by cost of being wrong

StrengthMechanismWhen
One-promptrun the check & iterate in the same messagecheap, low stakes
Goal condition/goal condition re-checked every turnmulti-step in one session
Stop-hooka Stop hook blocks the turn from ending until it passesmust-not-forget invariants
Second opiniona fresh subagent tries to refute the resulthigh reversal cost
Adversarial review before "done". Default: a native fresh-subagent review of the diff against the acceptance criteria (the bundled /code-review skill) — the agent doing the work isn't the one grading it. Tell it to flag only correctness / requirement gaps. Opt-in cross-model upgrade: the OpenAI Codex plugin (/codex:adversarial-review) — a luxury, not a dependency.
§6 Layer 3

Point at what exists; add only what's new

  • ·Context loaded? CLAUDE.md / rules / a curated raw → wiki → outputs knowledge folder — the context the agent stands on.
  • ·Reusable? If you'll do this repeatedly, make it a skill.
  • ·Guardrails. always-do (/permissions) · ask-first (auto-mode) · never-do (a PreToolUse hook, exit 2, on the build's protected paths).
